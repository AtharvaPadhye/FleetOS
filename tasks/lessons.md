# FleetOS — Lessons

_Patterns learned from corrections and mistakes. Review at session start._

## 2026-09-26
- **Look at the UI, don't only trust tests.** In task 2.2 all unit tests and the axe scan passed while the primary button's text was invisible. A screenshot caught it. Rule: after any visual change, screenshot desktop + phone and look before committing.
- **tailwind-merge must know custom theme scales.** Custom `text-*` sizes (`text-body`, `text-label`, …) are read as colours by default, silently dropping real colour classes. Rule: every custom Tailwind scale added to `tokens.css` is also registered in `packages/ui/src/lib/cn.ts`, with a regression test.
- **Stop dev servers by port, not by name.** `pkill -f "next start"` missed the process (it renames itself `next-server`); Playwright then reused the stale server from an older build and served missing CSS, producing false failures. Rule: `kill $(lsof -tiTCP:3000 -sTCP:LISTEN)`, and Playwright only reuses a server when `PW_REUSE_SERVER` is set.
- **Check peer ranges before taking a new major.** TypeScript 7 breaks typescript-eslint (supports < 6.1), ESLint 10 breaks Next's lint plugins, corepack 0.34 can't launch pnpm 12. Rule: `npm view <pkg> peerDependencies` for the lint/build toolchain before upgrading a major.
- **Verify a regression test fails without the fix** before trusting it.
- **Don't state commit hashes from memory**; read them from `git log`.
- **Check contrast on every surface a token can sit on.** Task 1.4 checked text colours on 3 dark surfaces but not the popover (`overlay`); `fg-subtle` failed there at 4.21:1 and axe caught it in the ⌘K menu (task 2.5). Rule: contrast tables list all surfaces, and the e2e axe scan covers open dialogs/menus, not just pages.
- **Horizontally scrolling tables must be keyboard-reachable** (`role="region"`, `aria-label`, `tabIndex={0}` on the overflow wrapper) and `<dl>` children must be `<dt>`/`<dd>` (or `div` groups of them). Caught by axe on the phone viewport of the Rulebook page; the future DataTable component must bake this in.
- **Database tests must be hermetic.** A pgTAP test counted all rows in `profiles` and broke once e2e runs created real users locally; CI's fresh database hid it. Rule: assertions filter to the test's own fixture ids. (Repeated in 3.8c on a new table: every `count(*)` in a pgTAP file gets a `where org_id = <fixture>` before it's run, not after it fails.)
- **On-change streams are silent when nothing changes.** Treating "no telemetry for 15 min" as Offline marked parked-but-connected cars offline (258 h vs 3.8 h true in a simulated day). Connectivity, not data volume, decides reachability. Caught by testing the engine against the simulator's ground truth; keep that test.
- **Say what's missing once, not on every row.** A payout import into an org with no vehicles showed "No vehicle matches" on all rows; Akshat reasonably read it as the importer being broken. Rule: when a precondition is missing (no vehicles, no hubs, no data source), show one message that names it and the fix (design-system.md Part 4 "Empty").
- **Supabase caps every response at 1,000 rows, silently.** The first allocation run booked fixed costs for some orgs and not others because a cross-org vehicle query was truncated; a check script summing ledger lines was cut off the same way. Rule: any query that isn't scoped to one small org pages with `.range()` or aggregates in SQL (an RPC), and a verification that sums rows does it in SQL, not in the client.
- **CI starts a trimmed Supabase.** The e2e job excluded Realtime to save time, so realtime tests would have passed locally and failed in CI. Rule: when a feature starts depending on another Supabase service (realtime, storage, edge functions), update the `supabase start -x` list in `.github/workflows/ci.yml` in the same commit.
- **Supabase bulk inserts send every column of every row.** Rows with different keys insert nulls for the missing ones (hit twice in 3.8c/3.9 fixtures: `maintenance_h`, `is_demo`). Rule: in a multi-row insert, give every row the same keys, with explicit defaults.
- **Incremental refreshes must follow the data's time, not the wall clock.** The KPI rollup refreshed "from the last refreshed day", which is right for a live tick but wrong when a tick replays hours of simulated time across midnight; unit tests and fixtures passed because they never replayed. Caught only by the phase exit check that ran 24 h through the real tick and compared two independent calculations. Rule: anything incremental takes the window the new data covers as an input, and every phase exit includes an end-to-end run cross-checked against an independent computation.
- **Fixtures must exercise every computed path, not just the empty one.** 5.1's API fixture had no hours for a car, so revenue per available hour was always null and nobody noticed it wasn't whole cents; a real demo car broke the list API. Rule: an e2e fixture for a computed field includes the inputs that make it non-null (here: hours and revenue), and asserts the value.
- **Scratch scripts that must run inside the repo get a `.tmp.` name, which is gitignored.** A screenshot script copied into `apps/web` (to resolve `@playwright/test`) was committed with 5.2. Rule: name them `*.tmp.mjs`, and check `git status` for untracked files before `git add -A`.
- **Test fixtures in a Playwright project that skips a test mustn't rely on that test's side effects.** 5.4's API test expected an exception the desktop-only UI test created, so it failed on the phone project. Rule: each test creates what it asserts on (use the API for setup).
- **Tests that need a "not built yet" example must pick one from a late phase.** 5.5 broke two tests that used `/tickets` as the planned-endpoint example. Rule: use Phase 7 vehicle commands (or later) for such fixtures, and grep tests for an endpoint before building it.
- **SUBSTITUTE markers use `//` line comments, never JSDoc.** `pnpm substitutes` only matches line comments, so a marker inside `/** */` is silently invisible. Rule: after adding a marker, check that `pnpm substitutes` lists it.
- **A feature that needs a new Supabase service must turn it on in CI.** 5.5's attachment upload passed locally but failed in CI, which starts Supabase with `-x …,storage-api`. Rule: when code starts using storage, realtime, edge functions, etc., check the `supabase start -x` list in `.github/workflows/ci.yml` in the same commit.
