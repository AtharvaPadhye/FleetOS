# Task 2.6 (rest): CSP, Sentry, structured logs, Vercel previews

## Constraints
- Vercel project belongs to Atharva (Hobby); we can't read its logs or set its env. Everything public goes in
  `apps/web/.env.production`; every new secret is optional so the build and app work without it.
- Local dev and CI (`next start` in e2e) have no Sentry DSN: Sentry is a no-op there.
- The e2e suite runs the production build, so the CSP is exercised by every existing spec.

## A. Content-Security-Policy (SEC-5)
- `apps/web/src/lib/csp.ts`: `buildCsp({ nonce, dev, supabaseUrl, preview })` → header string. Pure, unit-tested.
  - `script-src 'self' 'nonce-…' 'strict-dynamic'` (+ `'unsafe-eval'` in dev only). No inline scripts otherwise.
  - `style-src 'self' 'unsafe-inline'`: React `style={}` attributes, Recharts and MapLibre need it; NFR SEC-5
    only forbids inline *scripts*.
  - `connect-src 'self'` + Supabase `https://` and `wss://` origin + `https://*.basemaps.cartocdn.com`
    `https://basemaps.cartocdn.com` (map style, tiles, glyphs). Sentry goes through a same-origin tunnel.
  - `img-src 'self' data: blob:` + Carto; `worker-src 'self' blob:` (MapLibre worker from `/vendor`);
    `font-src 'self'`; `object-src 'none'`; `base-uri 'self'`; `form-action 'self'`; `frame-ancestors 'none'`;
    `upgrade-insecure-requests` (prod only).
  - Preview deployments only: allow `https://vercel.live` (Vercel toolbar) in script/connect/frame/img.
  - `report-uri` → Sentry's CSP endpoint when a DSN is configured, so violations show up in Sentry.
- `proxy.ts`: generate a nonce per request, set `Content-Security-Policy` on request + response (Next applies the
  nonce to its own scripts). Keep the session/redirect logic as is; redirects carry the header too.
- `/docs/api` (Scalar, loads from jsDelivr with an inline config script): its own looser policy set in the route
  handler; documented.
- Static pages (`/design`, `/design/kpis`, not-found) get no nonce at build time → force dynamic with
  `await connection()` in the root layout (the app is already dynamic everywhere else).
- Remove the "added in task 2.6" note in `next.config.ts`; the other security headers stay there.

## B. Sentry (OBS-1)
- Add `@sentry/nextjs` (11.x; peer `next ^16` checked). Sentry org/project in **Akshat's** account (like
  Supabase), free Developer plan. DSN is public → `NEXT_PUBLIC_SENTRY_DSN` in `.env.production`.
- `instrumentation.ts` (server + edge `register`, `onRequestError = Sentry.captureRequestError`),
  `instrumentation-client.ts`, `app/global-error.tsx` capture. `withSentryConfig` in `next.config.ts` with
  `tunnelRoute: "/monitoring"` (same-origin, survives ad blockers, keeps CSP tight).
- Privacy: `sendDefaultPii: false`, no Replay, `beforeSend` strips cookies/auth headers/query tokens
  (`/r/<token>`, `/invite/<token>` paths scrubbed). Tags: `org_id`, `request_id`; `environment` from
  `VERCEL_ENV`; release = commit SHA (Sentry reads `VERCEL_GIT_COMMIT_SHA`).
- `apiRoute` handler: `Sentry.captureException` on 5xx with `org_id` + `request_id`; tick route likewise.
- Source maps: uploaded only when `SENTRY_AUTH_TOKEN` exists at build (optional, Atharva later); otherwise
  skipped silently.
- No DSN → SDK not initialised (local, CI, forks).

## C. Structured logs (OBS-2)
- `apps/web/src/lib/log.ts`: `log.info|warn|error(event, fields)` → one JSON line
  (`ts`, `level`, `event`, `request_id`, `org_id`, …), redacting keys like `token|secret|authorization|cookie|email`.
  Unit-tested.
- `proxy.ts` assigns `x-request-id` (keeps an incoming one ≤ 64 chars) on the request and response, so pages,
  server actions and `/api/v1` share one id; the API handler already reads it.
- Replace `console.*` in `lib/api/handler.ts` and `lib/engine/tick.ts`; tick logs one summary line per run.
